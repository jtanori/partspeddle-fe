# ADR-004: Marketplace Inventory Ownership Model (Refined)

**Status**: Accepted  
**Date**: June 14, 2026

## Context
PartsPeddle needs to support both standalone parts and harvested donor vehicles. Storing inventory details (price, condition, availability) on the `Part` entity creates drift for donor vehicles and prevents a unified marketplace model.

## Decision
- **Adopt `MarketplaceListing` Abstraction**: `listings` is the root asset type.
- **Listing vs. Inventory separation**: Listing data (price, status, seller) is separated from Inventory State (`PricingState`, `InventoryState`).
- **Schema Decoupling**: Specifications are owned by the `listing_id` via `listing_specifications` (EAV).
- **Inventory Specialization**: 
  - `parts` (Technical/Catalog data) linked to `listing_id`.
  - `donor_vehicles` (Vehicle metadata) linked to `listing_id`.

## Consequences
- **Positive**: Uniform API for querying all inventory specifications. Donor vehicles supported as first-class citizens.
- **Negative**: Requires careful join management for inventory states.
- **Future-Proofing**: The model acknowledges that `Price` and `Condition` belong to the Listing, not the Catalog Asset, allowing for future auction/offer logic.
