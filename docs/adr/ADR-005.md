# ADR-005: Canonical Specification Compiler Model

**Status**: Accepted  
**Date**: June 14, 2026

## Context
Previous implementations treated specification grouping and facet projection as reusable helper methods. This led to "semantic drift" where Search, PDP, and Wizard could interpret specification metadata differently.

## Decision
- **Adopt Compiler Pattern**: Replace `SpecificationResolver` with `SpecificationCompiler`.
- **Single Source of Truth**: All semantics (grouping, sorting, faceting) are computed in one deterministic pass via `compile()`.
- **Closed Output**: The compiler returns an immutable `CompiledSpecificationSet` that is strictly consumed by the UI/Search. 
- **Forbidden**: No interpretation surfaces allowed outside the compiler (no `reduce`, `sort`, or `facet` logic in the PDP mapper or Search engine).

## Consequences
- **Positive**: Eliminates semantic drift. Search and PDP are guaranteed to interpret specs identically.
- **Negative**: The compiler implementation is slightly more complex, but significantly reduces maintenance and audit surface area.
