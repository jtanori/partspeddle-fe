## Root causes

1. **Supabase migration drift**: staging DB has migration history records that are not present in the rebaselined `supabase/migrations/` directory. This is a known state mismatch that needs a migration-history repair or a fresh staging project before `supabase db push` can work from CI.
2. **Build-time secret availability**: `ALGOLIA_SEARCH_INDEX_NAME` is required at build time after the P4.5 Algolia env refactor, but Fly.io image builds do not receive it. Options to resolve:
   - pass it as a Docker build arg via `fly deploy --build-arg` and consume it in the Dockerfile, or
   - make `algolia-client.ts` lazy/robust enough not to throw during static generation.
