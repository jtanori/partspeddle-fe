# ADR-001: Catalog Ownership Model

**Status**: Accepted  
**Date**: June 13, 2026

## Context
The system requires a clear distinction between data originating from manufacturer/catalog sources vs. marketplace-specific listing data.

## Decision
- **Universal Attributes**: (`brand`, `price`, `condition`) are owned by the `parts` table.
- **Specification Attributes**: (`voltage`, `bolt_pattern`) are governed by `catalog_spec_definitions` and populated in `part_specifications`.
- **EAV Mapping**: We will use a Typed-EAV model (`part_specifications`) with strict constraints to ensure data integrity and prevent schema bloat.

## Consequences
- **Positive**: Schema stability for new categories. No hardcoded logic in the frontend.
- **Negative**: Increased complexity for the query layer (joins required for specifications).
