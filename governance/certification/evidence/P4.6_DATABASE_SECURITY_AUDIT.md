# P4.6 — Full Database Security Audit

## Scope

This audit covers the Supabase Postgres schema, RLS policies, `SECURITY DEFINER`
functions, Edge Function authorization, and service-role key usage for the
VinTrack / PartsPeddle marketplace after the P4.3 migration rebaseline and the
P4.5 deploy exercise.

## Schema snapshot

A fresh public-schema dump was pulled from the linked staging project on
2026-07-07 and redacted for hard-coded JWTs:

- `supabase/baseline/remote_20260707_public.sql`

The dump revealed significant drift from the repo baseline: the staging database
still contains legacy synchronous webhook triggers
(`sync-algolia-webhook` on `parts`, `notify-new-message` on `messages`) that call
Edge Functions using a hard-coded service-role JWT in the trigger definition.
That JWT must be treated as exposed and rotated immediately.

## Critical findings fixed in this branch

1. **Missing `public.user_roles` table**
   The role-sync trigger inserted into a table that was not defined in the
   rebaseline schema or migrations. Added the table, PK/FK, role check,
   timestamps, RLS, and a self-read policy.

2. **Role self-escalation on sign-up**
   `handle_new_user_role` previously set the role from
   `NEW.raw_user_meta_data ->> 'role'`, allowing a client to request `admin` at
   sign-up. It now hard-codes `'buyer'`.

3. **`SECURITY DEFINER` functions without `search_path`**
   `fn_audit_log_changes`, `fn_enqueue_search_event`, `handle_part_sale_lock`,
   and `handle_new_user` were missing a restricted `search_path`. Added
   `SET search_path = public, pg_temp` to all of them.

4. **Unauthenticated `analyze-part-image` Edge Function**
   The function accepted image uploads from any caller and consumed Gemini API
   credits. Added Bearer JWT verification using `SUPABASE_ANON_KEY`.

5. **Legacy synchronous webhook triggers with embedded service-role JWT**
   The staging database contains `sync-algolia-webhook` and `notify-new-message`
   triggers that invoke Edge Functions with a hard-coded service-role token.
   The rebaseline migration now drops these triggers on replay. The exposed JWT
   must be rotated and the triggers removed from staging/production manually
   until the migration deploy path is repaired.

## Non-critical gaps moved to P6

These are tracked in `governance/planning/master-plan.md` under the **P6 — Security
hardening follow-ups** section and will be filed as GitHub issues:

- Tighten overly permissive RLS policies (`part_images`, `fraud_events`,
  `risk_scores`, `offers`, `conversations`, `seller_owns_profile`).
- Restrict broad `GRANT ALL` and default privileges on sensitive tables and
  functions.
- Remove unused extensions if confirmed unused (`pg_net`, `pg_graphql`,
  `supabase_vault`, `uuid-ossp`).
- Replace `supabaseAdmin` usage in public read routes and analytics writes with
  anon/SSR clients or RLS-permitted inserts.
- Add replay protection (timestamp/nonce) to `sync-algolia-webhook` signature.
